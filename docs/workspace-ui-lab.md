# Workspace UI Lab

Workspace UI Lab은 실제 Workspace 화면을 곧바로 수정하지 않고도 트리 UI의 시각 언어와 상호작용 조합을 빠르게 비교하기 위한 개발 전용 실험실이다.

이 Lab의 목표는 하나의 완성된 시안을 전시하는 것이 아니다. 테마, 노드, 연결선, 배치처럼 서로 다른 설계 결정을 독립적인 슬롯으로 분리하고, 여러 조합을 안전하게 시험한 뒤 검증된 결정을 실제 제품으로 옮길 수 있게 하는 것이 핵심이다.

구현 구조와 확장 방법은 [`src/widgets/workspace-lab/README.md`](../src/widgets/workspace-lab/README.md)에서 설명한다.

## 사용 범위

- 개발 환경의 `/dev/workspace-lab`에서만 접근한다.
- production 빌드에서는 `notFound()`로 차단한다.
- 실제 사용자 데이터 대신 재현 가능한 시나리오 fixture를 사용한다.
- 시각적 결정과 배치 규칙을 비교하는 데 집중한다.
- 실제 Workspace의 저장, 편집 명령, 서버 통신, 인증, undo/redo는 다루지 않는다.
- 운영 트리 편집기의 ELK 배치 로직을 대체하지 않는다.

Lab 코드는 제품 코드가 의존하는 기반 모듈이 아니다. 실험 결과를 제품에 반영할 때는 Lab 컴포넌트를 직접 import하기보다, 검증된 토큰·프리셋·규칙을 제품의 책임에 맞는 모듈로 옮긴다.

## 실험 단위

Workspace 화면은 다음 요소들의 조합으로 본다.

> 시나리오 × 전개 방향 × 배치 간격 × 컬러 테마 × 형태 × 노드 모양 × 노드 밀도 × 연결선 × 연결 포인트 × 접기 버튼 × 캔버스 × 상태 × 주변 패널

Inspector는 이 조합을 바꾸는 제어판이고, Preview는 선택된 조합의 결과를 보여주는 샌드박스다. 각 옵션은 다른 옵션을 암묵적으로 바꾸지 않는 것을 원칙으로 한다.

연결선처럼 원자 속성이 많은 슬롯은 자주 쓰는 조합을 제안 preset으로 제공한다. preset을 선택하면 관련 속성을 한 번에 바꾸고, 접힌 커스텀 영역을 열면 각 속성을 다시 독립적으로 조정할 수 있다. preset과 일치하지 않는 조합은 자동으로 `커스텀`으로 표시한다.

현재 기본 조합은 다음과 같다.

- 균형 시나리오
- 세로 전개, 균형 간격
- `Draft 01 · Quiet Focus` 컬러 테마, 겹그림자 형태
- 둥근 사각형, `Comfortable` 밀도
- 레이아웃 기본 형태, 실선, Regular 두께, Theme edge 색상, 100% 투명도, 효과 없음
- 도트 연결 포인트, 플로팅 원형 접기 버튼
- 두 패널 모두 고정 배치, 기본 너비, 패널 표면, 구분선, Comfortable 밀도
- 도트 그리드 캔버스

## 설계 원칙

### 데이터, 배치, 표현을 분리한다

시나리오는 트리 데이터와 상태를 제공하고, layout은 좌표와 연결 방향을 계산하며, theme과 visual slot은 표현만 결정한다. 새 스타일을 시험하기 위해 fixture나 배치 알고리즘을 복제하지 않는다.

### 노드 밀도와 노드 간격을 구분한다

노드 밀도는 노드 자체의 크기, 내부 여백, 글자 크기를 정한다. 배치 간격은 형제 사이와 깊이 사이의 외부 공간을 정한다. 실제 좌표는 선택된 노드 크기와 외부 간격을 합산해 계산한다.

이 분리를 지켜야 `Compact + 넓게`, `Spacious + 촘촘하게`처럼 서로 다른 목적의 조합을 올바르게 비교할 수 있다.

밀도에서 계산한 크기는 최초 렌더를 위한 예상값이다. 렌더 이후에는 React Flow가 측정한 노드별 실제 폭과 높이를 사용해 다시 배치한다. 콘텐츠 편집이나 줄바꿈으로 크기가 달라지면 측정값 변경을 한 프레임 단위로 모아 layout을 갱신한다.

### 연결선이 요구하는 최소 공간을 보장한다

세로·가로 배치의 직각 연결선은 두 번 꺾일 공간이 필요하다. 따라서 선택한 단계 간격이 너무 작더라도 SmoothStep routing이 요구하는 최소 간격을 하한으로 적용한다. 단계별 실제 최대 높이 또는 폭 뒤에서 다음 단계를 시작하므로 콘텐츠 길이가 달라져도 이 공간을 유지한다.

현재 하한은 다음 식으로 계산된다.

```text
minimum gap = offset × 2 + center clearance
            = 20 × 2 + 8
            = 48px
```

이 값은 임의의 디자인 토큰이 아니라 연결선의 기하학적 제약이다. routing 값을 바꾸면 테스트와 최소 간격도 함께 갱신해야 한다.

### 캔버스 표면과 패턴을 분리한다

컬러 테마의 `canvas` 토큰은 바탕색을 정하고, 캔버스 프리셋은 패턴과 질감 표현을 정한다. 프리셋의 색도 컬러 테마 token에서 파생해 컬러 테마를 바꿔도 함께 따라간다. React Flow의 renderer는 투명하게 유지해야 루트에 적용된 배경과 페이퍼 질감이 가려지지 않는다.

### 프리셋은 조합으로 검증한다

개별 프리셋이 보기 좋은지만 확인하지 않는다. 특히 다음 경계 조합을 함께 확인한다.

- 세로 + 촘촘하게 + 원형 노드
- 가로 + Spacious 노드
- 방사형 + 깊은 트리
- 각 캔버스 프리셋 + 밝고 어두운 edge 색상
- empty 시나리오 + 패널 표시 조합

## 제품 반영 기준

Lab의 결과를 실제 Workspace로 옮기기 전에 다음을 확인한다.

1. 대표 시나리오와 경계 조합에서 구조가 읽히는가?
2. 새 프리셋이 다른 슬롯의 동작을 암묵적으로 바꾸지 않는가?
3. 키보드 포커스, 대비, 작은 viewport에서 사용할 수 있는가?
4. 배치와 연결선에 겹침이나 불필요한 굴곡이 없는가?
5. 실제 편집 상태와 데이터 규모에서도 같은 결정이 유효한가?
6. 제품 코드에서 재사용할 최소 단위가 토큰인지, 타입인지, 컴포넌트인지 명확한가?
7. 선택한 결정에 회귀 테스트를 붙일 수 있는가?

Lab은 결정을 빠르게 만드는 곳이고, 실제 Workspace는 그 결정을 제품의 데이터 흐름과 접근성, 성능 요구에 맞게 책임지는 곳이다.
