# 강의 대본 생성 규칙 (제안)

백엔드가 트리로부터 강의 대본을 생성할 때 따를 규칙과 프론트엔드와의 응답 계약을 제안한다. 데모의 요구사항은 [강의 웹 플레이어 데모](./lecture-player.md)에 있다.

핵심 원칙은 **LLM은 문장만 쓰고, 어떤 노드를 어떤 순서로 설명할지는 백엔드 코드가 정한다**는 것이다.

## 책임 나누기

| 항목             | 정하는 쪽        | 이유                                                                              |
| ---------------- | ---------------- | --------------------------------------------------------------------------------- |
| 구간 목록과 순서 | 백엔드 코드      | LLM이 노드 ID를 고르면 없는 노드를 만들 수 있다. 트리에서 정하면 항상 유효하다    |
| 구간별 문장      | LLM              | 생성이 필요한 부분은 이것뿐이다                                                   |
| 자막 시각        | 음성을 만드는 쪽 | TTS가 붙으면 오디오 길이에서 나온다. 그 전에는 프론트엔드가 글자 수로 어림한다    |
| 카메라 대상·배율 | 프론트엔드       | "설명 노드와 직계 자식"처럼 구조에서 계산되는 화면 문제라 서버 계약에 넣지 않는다 |

## 응답 계약

```ts
{
  lectureId: number;
  title: string;
  treeVersion: string; // 강의를 만든 시점의 트리 버전
  segments: Array<{
    nodeId: number; // 이 구간이 설명하는 노드
    sentences: Array<{
      text: string;
      // TTS 연동 후 추가: audioUrl, durationMs
    }>;
  }>;
}
```

현재 프론트엔드 타입(`src/entities/lecture/model/types.ts`)의 `camera`와 `startMs`·`endMs`는 목데이터라서 직접 적어 둔 값이다. 서버 연동 시 위 계약으로 줄이고, 두 값은 프론트엔드에서 파생한다. 노드 이름 경로(`nodePath`)는 `nodeId`로 바뀐다.

## 구간 규칙

백엔드 코드가 트리 구조에서 결정한다.

- **순서**: 루트부터 DFS 전위 순회한다. 형제는 `orderId` 순서를 따른다. 부모의 개요를 먼저 말하고 자식으로 내려가는 흐름이다.
- **구간 하나는 노드 하나를 설명한다.**
- **포함할 노드**: 큰 트리에서 모든 노드를 구간으로 만들면 강의가 너무 길어진다. 최대 구간 수를 넘으면 깊은 리프를 부모 구간에 합치고, 합쳐진 리프는 부모 설명 안에서 함께 언급한다.
- **LLM에 넘기는 재료**: 노드 `name`, `memo`, 루트부터의 경로, 다음 구간 노드 이름. 경로가 있어야 같은 이름도 맥락에 맞게 설명한다.

## 문장 규칙

프론트엔드가 문장을 하나씩 음성으로 읽고 자막으로 띄우므로 다음을 지킨다.

- **한 항목에 한 문장**만 담고, 길이 상한(예: 60자)을 둔다. 자막 한 줄에 들어가야 하고, 브라우저 음성 합성은 긴 발화를 도중에 끊는다.
- **구간당 2~4문장**으로 쓴다.
- **소리 내어 읽을 수 있는 글만 쓴다.** 마크다운, 이모지, 괄호, 코드, 기호(`→`, `O(n)`)는 TTS가 어색하게 읽는다. `O(n)`은 "데이터 수에 비례하는 시간"처럼 풀어 쓴다.
- **노드 이름을 그대로 언급한다.** 문장 단위 노드 강조나 자막 속 노드 링크를 이름 매칭으로 붙일 수 있다.
- **구간의 마지막 문장은 다음 구간으로 잇는다.** 예: "다음으로 스택을 보겠습니다." 마지막 구간은 강의를 마무리한다.

## 생성과 검증

LLM 출력은 JSON 스키마(구조화 출력)로 받고, 서버가 검증한 뒤 저장한다.

- 구간 수와 `nodeId`가 백엔드가 정한 목록과 일치한다.
- 빈 구간이 없다.
- 문장 길이와 구간당 문장 수가 규칙 안에 있다.

검증에 실패하면 실패한 구간만 다시 생성한다.

## 트리가 바뀌었을 때

트리는 계속 편집되므로 생성한 강의가 낡을 수 있다.

- 강의에 `treeVersion`(또는 생성 시각)을 저장한다. 트리가 그보다 새로우면 다시 만들어야 하는 상태임을 응답에 담는다.
- 대상 노드가 삭제된 구간은 강조와 카메라 이동 없이 자막만 진행한다. 현재 프론트엔드 동작과 같다.
- 노드 이름만 바뀐 경우는 그대로 재생해도 된다.

## 정해야 할 것

1. 최대 구간 수와 리프를 부모 구간에 합치는 기준
2. `memo` 밖의 일반 지식을 대본에 허용할지. 허용한다면 `memo`를 우선한다.
3. 생성을 동기 요청으로 처리할지, 작업 큐로 처리할지
4. 트리가 바뀌면 자동으로 다시 생성할지, 사용자가 요청할 때만 생성할지
