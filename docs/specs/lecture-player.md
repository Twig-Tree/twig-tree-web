# AI 강의 웹 플레이어 데모

트리 화면에서 AI 강의가 재생되는 경험을 목데이터만으로 검증한다. 강의 음성에 맞춰 자막이 바뀌고, 설명 중인 노드가 강조되고, 카메라가 그 노드로 이동한다.

서버와 데이터베이스는 이후에 구현한다. 이번 데모는 프론트엔드만 다룬다.

구현 구조와 설계 이유는 [tree-editor README의 강의 데모 절](../../src/features/tree-editor/README.md#강의-데모)에 있다.

## 범위

### 포함

1. 강의 시작과 일시정지
2. 강의 음성 재생
3. 음성 재생에 맞춘 자막 표시
4. 현재 설명하는 노드 강조
5. 관련 노드로 부드러운 카메라 이동
6. 다음 강의 장면으로 진행
7. 강의 종료 상태 표시

### 제외

- 백엔드 API, DB 스키마 변경, Redis 연동
- LLM을 통한 강의 대본 생성
- 외부 JSON의 런타임 스키마 검증
- TTS API 연동
- 강의 콘텐츠와 사용자별 강의 이력의 서버 저장
- MP4 생성과 내보내기
- 강사 아바타 생성
- 강의 생성 작업 큐와 서버 측 비동기 처리

강의 대본은 프론트 데모 강의로만 제공한다. 데모 강의도 서버가 강의를 내려줄 때 사용할 노드 ID 계약을 따르지만,
이번 단계에서는 강의 조회 API를 호출하지 않는다. 런타임 검증과 실제 API 연결의 후속 요구사항은
[강의 대본 계약](./lecture-script-contract.md)에 기록한다.

목데이터를 서버 데이터로 바꾸기 어렵지 않게 구조를 잡는다. 다만 API 추상화나 서비스 계층을 미리 만들지는 않는다.

## 사용자 경험

### 재생 흐름

1. 트리 화면에서 강의를 시작한다.
2. 첫 장면에 연결된 노드로 카메라가 이동한다.
3. 그 비트의 음성이 재생된다.
4. 음성 재생에 맞춰 자막이 바뀐다.
5. 현재 설명 중인 노드가 강조된다.
6. 다음 장면이 시작되면 자막, 강조, 카메라가 함께 갱신된다.
7. 마지막 장면이 끝나면 완료 상태를 표시한다.

강의 플레이어는 기존 트리 편집 경험과 충돌하지 않아야 한다. 강의 중에도 트리를 편집하고 드래그할 수 있다.

### 음성

실제 TTS를 호출하지 않으므로 다음 순서로 재생 방법을 정한다.

1. 사용할 수 있는 음성 파일이 있으면 그것을 쓴다.
2. 없으면 브라우저 `SpeechSynthesis`로 대본을 읽는다.
3. 음성 합성을 쓸 수 없는 환경에서는 재생 시간을 흘려보내는 대체 재생을 한다.

음성이 나오지 않는 환경에서 음성이 나오는 것처럼 보여서는 안 된다. 대체 재생 중임을 화면에 표시한다.

### 자막

- 현재 비트의 내레이션을 표시한다. 내레이션은 짧게 나눠 한 비트가 대체로 한 문장이 되게 한다.
- 일시정지하면 자막도 그대로 멈추고, 다시 재생하면 현재 비트를 처음부터 재생한다.
- 다음 장면으로 넘어가면 그 장면의 자막을 표시한다.

### 노드 강조

- 현재 장면의 중심 노드가 다른 노드와 분명히 구별되어야 한다. 대본에 강조 동작이 없어도 강조한다.
- 검색·태그 강조 등 기존 노드 스타일과 충돌하지 않는다.
- 강의가 끝나면 강조를 해제한다.
- 강의 상태가 트리 데이터 자체를 바꾸지 않는다.

### 카메라

- 현재 노드가 잘 보이도록 부드럽게 이동한다. 미리 만든 영상이 아니라 화면에서 실행되는 애니메이션이다.
- 필요하면 관련 노드가 함께 보이도록 배율을 조정한다.
- 노드 좌표가 아직 준비되지 않은 상황을 처리한다.

## 목데이터

- 강의 장면이 3개 이상이다.
- 각 장면이 실제 트리 노드에 연결된다.
- 장면마다 비트가 있고, 비트마다 내레이션이 있다.
- 카메라 이동 대상 노드가 있다.
- 재생, 일시정지, 다음 장면 이동, 종료를 모두 확인할 수 있다.

노드 ID는 저장할 때마다 새로 부여되므로 데모 강의에 ID를 고정하지 않는다. 노드 이름 경로로 지금 트리의 서버 ID를 찾아 대본을 만든다. 데모 트리는 다음 구조 중 하나를 편집기에서 직접 만든다. 맞는 데모가 없는 트리에서는 플레이어를 표시하지 않는다.

```text
컴퓨터 사이언스
├─ 자료구조
│  ├─ 배열
│  └─ 스택
└─ 알고리즘
   └─ 정렬

세계
├─ 유럽
│  ├─ 프랑스 ─ 파리
│  ├─ 독일 ─ 베를린
│  └─ 유로
└─ 아시아
   ├─ 대한민국
   │  ├─ 서울
   │  └─ 원
   └─ 일본
      ├─ 도쿄
      └─ 엔
```

## 재생 상태

음성, 자막, 노드 강조, 카메라가 서로 어긋나지 않도록 현재 장면과 비트 위치에서 화면 상태를 파생한다.

다음 상황에서도 상태가 꼬이지 않아야 한다.

- 음성이 겹쳐 재생되지 않는다.
- 일시정지 후 다시 재생할 수 있다.
- 다음 장면으로 넘어가면 이전 음성이 멈춘다.
- 화면을 떠나면 음성과 타이머가 정리된다.
- 버튼을 빠르게 여러 번 눌러도 상태가 맞는다.
- 강의가 끝난 뒤 처음부터 다시 재생할 수 있다.

## 완료 기준

1. 기존 트리 화면에서 강의 데모를 실행할 수 있다.
2. 목데이터만으로 전체 강의 흐름을 확인할 수 있다.
3. 대본의 `focus` 동작에 맞춰 카메라가 부드럽게 이동한다.
4. 현재 설명 중인 노드가 강조된다.
5. 자막이 비트에 맞춰 바뀐다.
6. 음성 재생 또는 표시된 대체 재생이 동작한다.
7. 일시정지, 재개, 다음 장면 이동, 강의 종료가 동작한다.
8. 기존 트리 편집 기능이 그대로 동작한다.
9. 타입 검사, lint, 관련 테스트를 통과한다.

## 강의 플레이어 운영 규칙

- 플레이어는 `LectureScript` 한 가지 형식만 재생한다.
- 대본은 장면과 비트로 구성하며, 한 비트에서 내레이션과 애니메이션을 함께 시작한다.
- 대본의 서버 노드 ID는 재생 전에 현재 편집기 세션의 clientId로 변환한다.
- ID 하나라도 현재 트리에 없으면 일부만 재생하지 않고 강의 전체 시작을 막는다.
- `persist` 시각 레이어는 같은 장면의 다음 비트와 일시정지 화면에서는 유지한다.
- 장면이 바뀌거나 강의가 종료·중단·언마운트되면 남아 있는 시각 레이어를 자동 정리한다.
- 일시정지 후 재개하면 현재 비트의 음성과 애니메이션을 처음부터 다시 실행한다.
- 애니메이션 실험 도구는 개발 전용 route `/dev/animation-lab`에서만 렌더링한다.
