# 학습 순서 제안 기능 프로토타입 기획

## 문서 정보

- 상태: 초안
- 대상 브랜치: `prototype/learning-path-suggestions`
- 목적: 구현 전에 제품 방향과 첫 프로토타입의 검증 범위를 합의한다.

## 배경

Twig Tree는 사용자가 분석을 원하는 문서나 자료를 입력하면 내용을 트리 형태로 분석하고 시각화한다. 기존 트리는 자료에 포함된 주제와 개념의 구조를 탐색하는 데 유용하지만, 사용자가 내용을 어떤 순서로 학습해야 하는지는 알려주지 않는다.

이번 기능은 기존 분석 트리를 기반으로 핵심 개념의 학습 순서를 제안하고, 사용자가 그 순서를 실제로 따라갈 수 있는 경험을 제공하는 것을 목표로 한다.

## 해결하려는 문제

분석 트리를 받은 사용자는 전체 자료의 구조를 볼 수 있지만 다음 판단은 직접 해야 한다.

- 어느 개념부터 시작해야 하는가?
- 다음에는 무엇을 학습해야 하는가?
- 어떤 개념이 다른 개념을 이해하기 위한 선수 지식인가?
- 전체 학습 과정에서 지금 어디까지 왔는가?

노드가 많고 관계가 복잡할수록 사용자는 트리를 탐색하는 데 인지 비용을 쓰게 된다. 이 기능은 시스템이 기본 학습 경로를 제시해 사용자의 선택 부담을 줄인다.

## 제품 가설

> 사용자는 분석 트리만 제공받을 때보다 핵심 개념의 선후 관계와 현재 위치가 포함된 학습 경로를 제공받을 때 자료를 더 쉽게 이해하고 끝까지 학습할 수 있다.

첫 프로토타입에서는 다음 질문을 검증한다.

1. 사용자가 학습 그래프를 보고 전체 학습 구조를 이해할 수 있는가?
2. 사용자가 별도의 고민 없이 다음 학습 단계로 이동할 수 있는가?
3. 학습 그래프와 슬라이드 모드 사이의 연결이 자연스럽게 느껴지는가?

## 목표

- 분석 트리에서 학습할 가치가 높은 핵심 지점을 선별해 제시한다.
- 핵심 지점 사이의 학습 선후 관계를 시각화한다.
- 사용자가 제안된 순서를 한 단계씩 따라갈 수 있게 한다.
- 전체 경로, 현재 위치, 완료 상태를 명확히 보여준다.
- 주 학습 흐름을 유지하면서 필요한 보충·심화 학습을 선택할 수 있게 한다.

## 첫 프로토타입의 비목표

첫 프로토타입에서는 학습 경로 UI의 효용을 우선 검증한다. 다음 항목은 범위에서 제외한다.

- 실제 AI 기반 학습 경로 자동 생성의 정확도 검증
- 사용자의 수준이나 목표에 따른 개인화
- 퀴즈, 시험, 점수 또는 정답 판정
- 여러 추천 경로의 비교
- 사용자가 경로를 직접 편집하는 기능
- 협업 및 사용자 간 진행 상태 공유
- 실제 서버와의 학습 진행 상태 동기화

## 핵심 개념

### 분석 트리

입력 자료의 주제와 개념을 계층적으로 분석한 기존 마인드맵이다. 노드 사이의 부모-자식 관계는 내용의 포함 관계를 나타낸다.

### 학습 경로

사용자가 자료를 학습할 때 따라갈 것을 권장하는 순서다. 분석 트리와 같은 원본을 사용하지만, 트리의 부모-자식 관계를 그대로 복제하지 않는다.

분석 트리는 **자료가 어떻게 구성되어 있는지**를 보여주고, 학습 경로는 **무엇을 어떤 순서로 배울지**를 보여준다.

### 학습 체크포인트

학습 경로에서 사용자가 하나의 단계로 경험하는 단위다. 분석 트리의 노드 하나와 대응할 수도 있고, 서로 밀접한 여러 노드를 하나로 묶을 수도 있다.

학습 체크포인트는 다음 정보를 가질 수 있다.

- 제목
- 학습할 핵심 개념과 설명
- 이 시점에 해당 개념을 학습하는 이유
- 연결된 원본 트리 노드
- 선수 체크포인트
- 다음 추천 체크포인트
- 선택 가능한 보충·심화 체크포인트
- 진행 상태

### 주 경로와 선택 경로

- 주 경로: 시스템이 기본으로 제안하는 학습 순서
- 선택 경로: 주 경로 중간에 진입할 수 있는 보충 또는 심화 학습

사용자는 선택 경로를 건너뛰어도 주 경로를 계속 진행할 수 있다. 첫 프로토타입에서는 복잡한 자유 탐색보다 하나의 명확한 주 경로를 우선 제공한다.

## 학습 경로 구성 원칙

1. 분석 트리의 부모-자식 관계를 학습 선후 관계로 간주하지 않는다.
2. 각 체크포인트는 사용자가 한 단계로 받아들일 수 있는 분량이어야 한다.
3. 주 경로에서는 다음 행동이 항상 명확해야 한다.
4. 선택 경로는 주 경로의 진행을 방해하지 않아야 한다.
5. 현재 위치와 완료 상태는 그래프와 슬라이드에서 동일하게 유지되어야 한다.
6. 경로가 갈라지더라도 시스템이 권장하는 기본 방향은 명확하게 표시한다.

첫 프로토타입의 권장 구조는 다음과 같다.

```text
개요 → 핵심 개념 → 작동 원리 → 적용 사례 → 종합 정리
                    ├─ 기초 보충
                    └─ 심화 탐구
```

## 사용자 경험

### 기본 흐름

1. 사용자가 자료를 입력해 기존 분석 트리를 생성한다.
2. 시스템이 분석 트리를 바탕으로 학습 경로를 제안한다.
3. 사용자가 학습 그래프에서 전체 경로를 확인한다.
4. 사용자가 시작 체크포인트를 선택해 학습을 시작한다.
5. 슬라이드 모드에서 체크포인트를 하나씩 학습한다.
6. 완료 상태와 현재 위치가 학습 그래프에 즉시 반영된다.
7. 사용자가 선택 경로를 학습하거나 건너뛴 뒤 주 경로로 돌아온다.
8. 마지막 체크포인트를 완료하면 전체 학습 완료 상태를 확인한다.

### 두 UI의 관계

학습 그래프와 슬라이드 쇼는 서로 분리된 기능이 아니라 같은 학습 경로와 진행 상태를 표현하는 두 가지 모드다.

| UI | 답해야 하는 질문 | 주요 역할 |
| --- | --- | --- |
| 학습 그래프 | 전체 과정에서 나는 어디에 있는가? | 전체 구조, 의존 관계, 분기와 진행 상태를 보여준다. |
| 슬라이드 모드 | 지금 무엇을 학습해야 하는가? | 현재 개념에 집중하고 다음 행동을 안내한다. |

첫 프로토타입은 **학습 그래프를 내비게이션으로 두고, 선택한 체크포인트를 슬라이드형 학습 패널에서 진행하는 통합형 UI**를 기본 방향으로 한다.

## 학습 그래프

학습 그래프는 분석 트리와 시각적·개념적으로 구분한다. 그래프의 연결선은 주제의 포함 관계가 아니라 학습 선후 또는 선수 관계를 나타낸다.

### 노드 상태

- 완료: 학습을 마친 체크포인트
- 현재: 지금 학습 중인 체크포인트
- 학습 가능: 바로 시작하거나 이동할 수 있는 체크포인트
- 잠김: 선수 체크포인트를 아직 완료하지 않은 체크포인트
- 선택: 주 경로 진행에 필수적이지 않은 보충·심화 체크포인트

### 주요 동작

- 체크포인트를 선택해 요약 정보를 확인한다.
- 학습 가능한 체크포인트에서 슬라이드 학습을 시작한다.
- 현재 위치와 완료한 경로를 한눈에 확인한다.
- 선택 경로에 진입하거나 주 경로로 복귀한다.

잠긴 체크포인트를 클릭했을 때는 단순히 동작을 막기보다 먼저 학습해야 하는 체크포인트를 안내한다.

## 슬라이드 모드

슬라이드 모드는 하나의 체크포인트에 집중해 학습하고 다음 단계로 이동하는 화면이다.

### 화면 요소

- 현재 체크포인트 제목
- 핵심 개념 설명
- 지금 이 내용을 학습하는 이유
- 관련 원본 트리 노드 또는 원본 자료로 이동하는 연결
- 현재 단계와 전체 진행률
- 이전 체크포인트 이동
- 학습 완료 및 다음 체크포인트 이동
- 보충·심화 경로 진입
- 전체 학습 그래프로 돌아가기

첫 프로토타입의 이해 상태는 `학습 중`과 `완료` 수준으로 제한한다. `이해했어요`와 `다시 볼게요`처럼 더 세부적인 상태는 프로토타입 검증 후 결정한다.

## 진행 상태

그래프와 슬라이드는 하나의 진행 상태를 공유한다.

- 체크포인트를 시작하면 현재 상태가 된다.
- 체크포인트를 완료하면 그래프의 표현과 전체 진행률이 갱신된다.
- 선택 경로의 완료 여부는 주 경로의 진행률과 구분해 표시할 수 있다.
- 새로고침 후에도 진행 상태가 유지되어야 한다.

첫 프로토타입에서는 브라우저 로컬 저장소를 사용할 수 있으며, 서버 저장은 범위에 포함하지 않는다.

## 첫 프로토타입 범위

- 고정된 샘플 분석 트리 1개
- 6~10개의 학습 체크포인트
- 하나의 주 경로
- 1~2개의 선택형 보충·심화 경로
- 학습 순서를 표현하는 의존성 그래프
- 체크포인트를 진행하는 슬라이드 모드
- 그래프와 슬라이드 사이의 현재 위치 동기화
- 체크포인트 완료 상태와 전체 진행률
- 새로고침 후 진행 상태 유지

샘플 데이터는 학습 경로 자동 생성 결과처럼 구성하되, 첫 프로토타입에서는 고정된 데이터로 제공한다. 이를 통해 생성 로직의 품질과 UI 경험의 품질을 분리해서 검증한다.

## 완료 조건

첫 프로토타입은 다음 조건을 충족하면 완료된 것으로 본다.

- 사용자가 전체 학습 순서와 현재 위치를 그래프에서 식별할 수 있다.
- 사용자가 주 경로를 첫 체크포인트부터 마지막까지 진행할 수 있다.
- 사용자가 선택 경로에 진입한 뒤 주 경로로 복귀할 수 있다.
- 체크포인트 완료 상태가 그래프와 슬라이드에 일관되게 반영된다.
- 잠긴 체크포인트와 학습 가능한 체크포인트를 구분할 수 있다.
- 페이지를 새로고침해도 진행 상태가 복원된다.
- 기존 분석 트리와 학습 그래프의 목적 차이가 화면에서 드러난다.

## 검증 관찰 항목

프로토타입을 사용해 볼 때 다음 행동을 관찰한다.

- 첫 화면에서 사용자가 학습 시작 지점을 찾는가?
- 그래프의 화살표와 노드 상태를 설명 없이 이해하는가?
- 사용자가 다음 단계로 이동할 때 망설이는가?
- 선택 경로가 필수 경로로 오해되지 않는가?
- 슬라이드에서 그래프로 돌아왔을 때 현재 위치를 바로 찾는가?
- 기존 분석 트리와 학습 그래프를 서로 다른 목적으로 인식하는가?

## 미결정 사항

다음 항목은 첫 UI 프로토타입을 확인한 뒤 결정한다.

- 학습 그래프와 기존 분석 트리를 한 화면에서 전환할지, 별도 화면으로 분리할지
- 슬라이드를 전체 화면으로 표시할지, 그래프 옆 패널로 표시할지
- 잠긴 체크포인트의 탐색과 미리보기를 어느 수준까지 허용할지
- 완료한 체크포인트를 다시 열었을 때 현재 위치를 변경할지
- 선택 경로를 전체 진행률에 포함할지
- 체크포인트와 원본 트리 노드 사이의 연결을 어떻게 표현할지
- 이후 자동 생성 단계에서 사용자가 추천 경로를 수정할 수 있게 할지

## 후속 단계

1. 샘플 주제와 학습 체크포인트를 정한다.
2. 학습 그래프와 슬라이드 패널의 화면 구조를 설계한다.
3. 고정 데이터 기반의 첫 프로토타입을 구현한다.
4. 기본 흐름과 분기 흐름을 직접 사용하며 관찰 항목을 점검한다.
5. UI 구조를 보완한 뒤 자동 학습 경로 생성에 필요한 데이터 계약을 정의한다.
