# Tree Editor

Tree Editor는 사용자 행동, 서버 상태 동기화, 편집기 초기화, 노드 배치 및 React Flow 연결을 하나의 Feature에서 함께 다룬다. 서로 다른 생명주기와 변경 이유를 가진 로직이 한 디렉터리에 섞이지 않도록 `model`을 책임별로 나눈다.

## model 책임

- `actions`: 노드 추가·삭제·이동과 undo/redo 같은 사용자 행동을 mutation과 editor store에 연결한다. 페이지에는 개별 행동 훅 대신 `useTreeEditorActions` facade를 제공한다.
- `initialization`: 서버에서 조회한 트리 데이터를 editor store의 초기 상태로 반영한다.
- `sync`: 다른 탭·기기에서 바뀐 트리를 찾아 열려 있는 편집기에 반영한다. 편집 중인지 판단해 반영 시점을 정한다.
- `collapse`: 서브트리 접힘 상태를 관리한다. 접힘 store, 화면에 보일 노드·엣지 계산, 다른 탭과의 동기화를 담는다.
- `layout`: 노드와 edge의 배치를 계산하고 편집기 viewport를 조정한다.
- `drag`: 노드 드래그를 노드 이동으로 바꾼다. 놓을 자리를 정해 표시하고, 놓으면 노드 이동 action을 부른다.
- `search`: 검색어로 editor store의 노드를 찾아 결과 목록을 만든다.
- `tag`: 트리 태그 목록 query와 태그 생성·삭제를 묶은 `useTreeTags`, 고른 태그가 붙은 노드의 결과 목록을 만든다.
- `highlight`: 검색어·태그에 일치한 노드의 강조 상태를 관리하고, 지금 보이는 결과를 강조에 반영한다.
- `focus`: 결과 목록에서 고른 노드의 접힌 조상을 펼치고, 그 노드를 선택해 화면 가운데로 옮긴다. 태그를 고르면 보이는 태그 노드들을 한 화면에 모은다.
- `lecture`: 강의 재생 위치를 관리하고, 위치에 맞춰 내레이션을 읽고 대본의 연출 동작을 실행한다.
- `shortcuts`: 접속한 기기의 운영체제를 판별해 노드 동작 단축키 표를 고른다. 표와 누른 키를 동작으로 바꾸는 순수 함수는 `lib/shortcuts`에 둔다.
- `react-flow`: React Flow가 요구하는 인터페이스와 Tree Editor store 사이를 연결한다.
- `history`: 편집 단위 undo/redo 기록을 관리한다. 서버를 모르는 순수 store이고, 기록을 꺼내 요청하는 일은 `actions/undo-redo`가 맡는다(actions README의 "Undo/Redo").
- `treeStore.ts`: 편집 중인 노드와 edge를 관리한다.
- `types.ts`: Tree Editor에서 사용하는 node와 edge 타입을 정의한다.

## 노드 신원

편집기 노드의 `id`는 클라이언트가 정한다. 초기화 때는 `transformToFlowElements`가, 노드 추가 때는 `useAddNode`가 `createClientNodeId`로 만들고, 이 값은 세션 동안 바뀌지 않는다. 서버가 확정한 ID는 `data.serverId`에 담으며 아직 저장되지 않은 노드는 `null`이다.

두 값을 분리하는 이유는 두 가지다.

- **레이아웃이 한 번만 돈다.** 노드 `id`가 곧 서버 ID이면 응답이 도착할 때 ID를 교체해야 한다. 교체는 배치를 전혀 바꾸지 않으면서 구조 시그니처를 바꾸므로 배치 계산이 한 번 더 실행된다.
- **막는 대상이 편집이 아니라 서버 전송이 된다.** "서버에 아직 없다"는 판별이 `serverId === null`이므로 노드 ID의 생김새로 저장 여부를 추측하지 않는다.

이름은 `clientId`와 `serverId`로 구분한다. 예외는 React Flow가 이름을 소유하는 `Node.id` 하나이고, 거기 담기는 값이 곧 `clientId`다. 엣지의 `source`·`target`도 같은 신원을 가리킨다. `entities`는 노드를 가리키는 ID가 하나뿐이라 `nodeId`를 그대로 쓴다.

`serverId`가 아직 없는 노드에 대한 요청은 알림과 함께 막는다. 대기·큐 방식은 여러 편집을 묶어 저장하는 방식이 도입될 때 함께 정한다.

## 배열 순서와 레이아웃

**노드 배열의 순서가 형제 노드의 배치 순서를 결정한다.** 배열 순서는 단순 정렬 취향이 아니라 화면에 직접 드러나는 값이다.

`getLayoutedElements`는 부모를 첫 자식과 같은 높이에 두고 나머지 형제를 그 아래로 쌓는다. 다음 형제는 앞선 형제의 서브트리가 끝나는 곳 아래에서 시작한다. 노드 이동은 노드 배열만 다시 놓고 엣지 배열은 그대로 두어 두 배열의 순서가 어긋날 수 있으므로, 계산 전에 엣지를 자식 노드의 배열 순서로 정렬한다. 그래서 형제 순서를 바꾸려면 노드 배열만 바꾸면 된다.

정렬은 서버 데이터를 편집기 요소로 바꾸는 `transformToFlowElements`와 `getReconciledFlowElements`에서 `orderIndex` 기준으로 수행한다. query cache는 순서를 약속하지 않으므로 mutation이 노드를 어느 위치에 넣어도 무방하다. 화면에 넘기기 직전에만 보장하면 되기 때문이다.

## 노드 이동

노드를 끌어 놓으면 위치가 아니라 **부모와 형제 순서**가 바뀐다. 같은 부모 안의 순서 변경과 다른 계층으로의 이동을 모두 노드 드래그로 한다. 끈 좌표는 저장하지 않는다. 놓으면 노드를 끌기 전 좌표로 되돌리고, 이동이 반영되어 구조가 바뀌면 레이아웃이 새 자리에 놓는다.

### 엣지 편집은 막는다

핸들을 이어 엣지를 만드는 것(`nodesConnectable`)과 엣지 끝을 옮기는 것(`edgesReconnectable`)은 항상 끈다. 두 편집은 store만 바꾸고 서버에 저장되지 않아, 새로고침하면 사라졌다. 엣지를 새로 잇는 편집은 트리에서 성공하는 경우도 없다. 루트가 하나인 트리에서는 모든 노드에 이미 부모가 있기 때문이다. 부모 변경은 노드 드래그 하나로 모았다.

React Flow의 `Handle`은 `isConnectable`을 받지 않으면 `true`로 둔다. 그래서 `nodesConnectable`만 꺼서는 핸들까지 닿지 않고, `CustomNode`가 노드의 `isConnectable`을 핸들에 넘긴다.

### 놓기 규칙

`getDropTarget`이 놓은 지점(커서 위치)에서 가장 가까운 보이는 노드를 기준으로 삼고, 기준 노드의 어느 영역에 놓였는지로 목적지를 정한다. 레이아웃 방향이 `RIGHT`라 형제가 세로로 쌓이므로 위·아래로 앞뒤를 가른다.

| 놓은 영역              | 목적지 부모      | 자리              |
| ---------------------- | ---------------- | ----------------- |
| 기준 노드의 위쪽 1/4   | 기준 노드의 부모 | 기준 노드 바로 앞 |
| 기준 노드의 아래쪽 1/4 | 기준 노드의 부모 | 기준 노드 바로 뒤 |
| 기준 노드의 가운데 1/2 | 기준 노드        | 자식 맨 끝        |
| 노드에서 먼 곳         | —                | 원래 자리로 복귀  |

- **형제 사이의 빈칸만으로 정하지 않는다.** 한 부모의 마지막 자식과 다른 부모의 첫 자식이 같은 열에 붙어 있으면, 그 사이 빈칸이 어느 부모의 자리인지 정할 수 없다. 가까운 노드의 위·아래로 정하면 이 모호함이 없다.
- **가운데 영역이 있어야 잎 노드 밑으로 옮길 수 있다.** 자식이 없는 노드에는 "사이"에 놓을 자식이 없다.
- **놓을 수 없는 곳은 원래 자리로 돌아간다.** 자기 자신과 하위 노드(순환), 루트의 앞뒤(형제 없음), 원래와 같은 자리, 노드에서 `MAX_DROP_DISTANCE` 밖인 곳이 해당한다. 하위 노드는 판정 후보에서 빼고 조상 검사로 한 번 더 막는다.
- **접혀 숨겨진 자식도 순번에 넣는다.** 접힌 노드의 가운데에 놓으면 숨겨진 자식들 뒤에 붙는다. 이때 이동 전에 그 노드를 펼친다.
- 루트는 끌 수 없다. 화면에 넘기는 노드 목록에서 루트만 `draggable: false`로 둔다.

### 놓을 자리 표시

끄는 동안 `getDropIndicator`가 목적지를 화면에 표시할 모양과 위치를 정하고, `DropIndicatorOverlay`가 그린다. 형제 앞뒤면 기준 노드와 이웃 형제 사이 빈칸의 가운데에 삽입선을 그린다. 자식이면 기준 노드를 둘러싼 점선 테두리를 그린다. 선택·검색 강조와 구분되도록 점선과 다른 색을 쓴다.

표시는 `ViewportPortal` 안에 그려 노드와 같은 flow 좌표계로 이동·확대된다. 표시 상태는 화면에서만 쓰는 값이라 editor store가 아니라 `useMoveNodeByDrag`의 로컬 상태에 둔다.

## 초기화 규칙

editor store 초기화는 트리당 한 번만 수행한다. `useInitializeTree`는 `currentTreeId === treeId`이면 건너뛴다.

이 초기화를 다시 돌리면 세 가지가 무너진다. `mapToVisualNodes`가 모든 `position`을 원점으로 되돌리므로 레이아웃이 다시 계산되어야 하고, 노드 신원도 새로 부여되므로 선택 상태와 편집 중인 대상을 가리키던 참조가 끊기며, 편집 중이라면 내용까지 덮어쓴다. 편집기를 연 채로 서버 값을 반영하는 일은 이 경로가 아니라 아래 "다른 곳의 변경 반영"이 맡는다.

대신 편집기를 벗어날 때 `resetTree`로 store를 비운다. 비우지 않으면 재진입해도 초기화가 일어나지 않아 그 사이의 서버 변경이 화면에 반영되지 않는다. 이 호출은 마운트·언마운트 전용 effect에 둔다. 초기화 effect의 cleanup으로 붙이면 deps가 바뀔 때마다 store가 비워진다.

여러 변경을 묶어 저장하는 방식이 도입되면 언마운트가 곧 미저장 편집 폐기가 되므로 이 규칙을 재검토한다.

## 다른 곳의 변경 반영

트리는 소유자 한 명만 편집하지만 같은 사람이 여러 탭·기기에서 열 수 있다. 실시간 동기화 없이, 탭으로 돌아올 때 다시 조회해 바뀐 것을 찾는다. `sync/useSyncExternalTreeChange`가 맡는다.

### 감지

`useGetTreeQuery`는 포커스 재조회를 끄고, 이 hook이 `focusManager`의 포커스 복귀 때 "직전 캐시 읽기 → 다시 조회 → 비교"를 한 흐름으로 실행한다. 라이브러리에 맡기면 비교 기준을 잡기 전에 캐시가 덮이고, 이 탭의 무효화 재조회와 구분할 수 없다.

- **비교는 이 hook이 조회한 결과만 한다.** 캐시는 서버 응답으로만 갱신되므로, 삭제 뒤 무효화 재조회까지 비교하면 자기 변경을 외부 변경으로 오판한다.
- **이 탭의 요청과 겹치면 비교를 버린다.** 시작할 때 트리 mutation이나 조회가 진행 중이거나 재조회 중에 mutation이 시작되면, 요청이 모두 끝난 뒤 한 번 더 확인한다.
- **비교는 순서와 무관하다**(`isSameTreeNodes`). 캐시는 노드 순서를 약속하지 않고, 태그를 붙이면 끝에 덧붙이므로 `tagIds` 순서도 서버와 다를 수 있다. version은 비교에 넣는다. 다른 곳에서 내용을 바꿨다가 되돌리면 내용은 같아도 version이 달라, 놓치면 다음 저장이 잘못 충돌한다.
- **저장이 거절되어도 확인한다.** 충돌과 노드 없음 응답은 다른 곳에서 트리가 바뀌었다는 신호다. `focusManager`는 `visibilitychange`로만 포커스를 판단하므로, 나란히 띄운 창은 이 신호로 맞춘다.

### 반영

변경을 찾아도 편집 중이면 미룬다(`useIsEditingTree`). 이름 입력창이 열려 있거나, 메모에 저장하지 않은 입력이 있거나, 노드를 끄는 중이거나, 트리 mutation·구조 편집·강의 재생이 진행 중인 경우다. undo/redo는 요청 사이에 mutation이 0개인 순간이 있어 mutation 수만 보지 않는다.

끝나면 그 시점의 캐시를 `getReconciledFlowElements`로 store에 넣는다. 미루는 동안 저장한 이 탭의 편집도 캐시에는 들어 있다.

- **노드 신원을 이어 쓴다.** `serverId`가 같은 노드는 `clientId`, 좌표, 선택을 물려받고 서버 데이터만 바뀐다. 새 신원을 만들면 모든 노드가 다시 마운트되어 깜빡이고, 강조와 레이아웃 뒤로 맡긴 이동이 옛 ID를 가리킨다. 구조가 같으면 레이아웃도 돌지 않는다.
- **접힘과 강조는 건드리지 않는다.** 접힘을 다시 복원하면 새 집합이 만들어져 `useNodeTransition`이 접힘 변경으로 오인한다. 검색·태그 결과는 store에서 파생되므로 새 노드에 맞춰 다시 계산된다.
- **undo 기록은 비운다.** 기록의 대상이나 되돌릴 자리가 다른 곳의 변경으로 사라졌을 수 있다.
- 선택했던 노드가 사라지면 메모 패널과 우클릭 메뉴를 닫는다.

### 한계

나란히 띄운 창은 저장이 거절되기 전까지 오래된 화면일 수 있다. 이때 이 탭의 삭제 무효화나 재연결 재조회가 외부 변경을 먼저 캐시에 담으면 다음 비교에서 차이가 나지 않아, 새로고침 전까지 화면이 남는다. 이름·메모 덮어쓰기는 서버의 version 검사가 막는다.

## 접힘 상태

접힌 노드는 `serverId` 집합으로 `collapse/collapseStore`에 두고, 트리마다 `localStorage`의 `twig-tree:collapsed-nodes:{treeId}` 키에 저장한다. 편집기 노드 `id`는 초기화 때마다 새로 만들어지므로 새로고침 뒤에도 같은 노드를 가리키는 값은 `serverId`뿐이다.

### editor store와 따로 두는 이유

- **생명주기와 부수효과가 다르다.** 접힘 상태는 `localStorage`와 다른 탭의 `storage` 이벤트를 따라 바뀐다. editor store는 서버 데이터와 맞춰 가는 편집 상태다.
- **접기·펼치기는 undo 대상이 아니다.** 서버와 무관한 화면 상태다.

같은 이유로 React Flow 노드의 `hidden` 속성도 쓰지 않는다. `nodes`에 두면 삭제 기록과 실패 복구용으로 보관하는 노드에 `hidden`이 함께 담겨, 되살릴 때 그때의 접힘 상태가 돌아온다. 숨길 노드는 `useVisibleElements`가 배열에서 걸러 내고, 걸러 낸 배열을 레이아웃 계산과 화면 표시에 함께 넘긴다.

### 계층 단위로 접고 펼치기

도구 모음의 `−`, `+`는 트리를 몇 계층까지 보여 줄지 정한다. 화면의 계층은 루트를 1로 세고, 코드의 깊이는 루트를 0으로 센다.

- **접힘 집합을 통째로 바꾼다.** `expandToDepth`는 고른 깊이의 노드를 접고 나머지는 펼쳐, 노드별로 접어 둔 상태를 남기지 않는다. 접힘은 undo 대상이 아니므로 되돌릴 수 없다.
- **현재 계층은 보이는 가장 깊은 곳이다.** 노드별로 접어 가지마다 깊이가 달라도 숫자 하나로 보여 주기 위해서다.
- **가장 깊은 가지가 보여도 숨겨진 노드가 있으면 `+`를 막지 않는다.** 숫자만 보고 막으면 접힌 가지를 여기서 펼칠 수 없다.
- **바꾼 뒤 화면을 다시 맞춘다.** 노드별 접기는 보던 지점을 유지하지만, 계층 조절은 전체 모양을 보려는 동작이다. 접힘을 바꾸기 전에 `fitTreeViewAfterNextLayout`으로 맡겨, 새 배치가 끝난 다음에 부드럽게 맞춘다. 보이는 노드가 그대로면 레이아웃이 돌지 않으므로 맡기지 않는다. 맡겨 두면 나중의 관계없는 편집 뒤에 화면이 움직인다. 처음 열 때의 맞춤만 애니메이션 없이 한다.
- **좌표는 화면에서만 옮긴다.** 접힘이 바뀌면 `useNodeTransition`이 이전 좌표에서 새 좌표로 옮기며 그릴 노드 목록을 만든다. store에는 최종 좌표만 있어 드롭 판정·레이아웃·undo는 전환을 모르고, 연결선은 React Flow가 노드 좌표로 그리므로 함께 움직인다. 새로 나타난 노드는 이전 화면에 있던 가장 가까운 조상의 자리에서 투명하게 출발하고, 나타나는 노드의 연결선은 도착한 뒤에 드러난다. 접혀서 사라지는 노드는 이미 데이터에서 빠지므로, 화면에 넘기는 목록에만 조작을 막은 더미(`GhostNode`)를 더해 계속 보이는 가장 가까운 조상의 자리로 들여보낸다. 더미는 store에 없어 드롭 판정·레이아웃·선택이 알지 못한다. 사라지는 노드의 연결선은 움직이기 시작하며 먼저 흐려진다. 전환 중에 다시 접거나 펼치면 처음부터 시작하지 않고, 그리던 좌표와 투명도에서 이어 간다. 더미도 마찬가지로 다시 나타나면 더미의 자리에서 제자리로 간다. 전환 중에는 React Flow가 아는 좌표가 중간값이므로, 화면 이동은 `useCameraMove`가 store의 최종 좌표로 잰다.

### 삭제된 노드의 ID는 복원할 때만 정리한다

저장된 접힘 목록에는 그 사이 삭제된 노드의 `serverId`가 남을 수 있다. 편집기에 들어와 `restoreCollapse`로 복원할 때, 조회한 트리에 있는 노드만 남기고 줄었으면 다시 저장한다.

- **세션 중 노드를 삭제할 때는 정리하지 않는다.** 삭제 요청이 실패하면 노드가 같은 `serverId`로 돌아오는데, 목록에서 이미 지웠다면 펼쳐진 채로 돌아온다. 삭제를 undo해 되살린 노드는 `serverId`가 새로 정해지므로 접힘 상태가 돌아오지 않는다.
- **다른 탭에서 받은 목록도 정리하지 않는다.** 이 탭에 없는 `serverId`는 다른 탭에서 방금 만든 노드일 수 있다. 걸러 낸 채로 이 탭이 저장하면 그 탭의 접힘을 덮어쓴다. 이 탭의 어떤 노드와도 맞지 않는 ID는 화면에 영향이 없고, 정말 삭제된 노드라면 다음 복원 때 걸러진다.

## 강조와 포커싱

검색 결과와 태그는 "결과 목록 → 강조 → 포커싱"이라는 같은 흐름을 쓴다. 세 개념은 서로 다르다.

| 개념   | 의미                                   | 대상 개수 | 구현                                       |
| ------ | -------------------------------------- | --------- | ------------------------------------------ |
| 선택   | 메모 패널과 노드 추가·삭제의 기준 노드 | 1개       | React Flow의 `node.selected`               |
| 강조   | 검색어·태그에 일치한 노드 표시         | 여러 개   | `highlight/highlightStore`, 선택과 다른 색 |
| 포커싱 | 해당 노드로 화면 이동                  | —         | 상태가 아닌 동작. `focus/useFocusNode`     |

다중 선택으로 강조를 대신하지 않는다. 선택 노드는 `selected`가 `true`인 첫 노드 하나로 읽으므로, 여러 개가 선택되면 메모 패널과 노드 추가·삭제가 그중 맨 앞 노드를 기준으로 동작한다.

### 강조를 editor store와 따로 두는 이유

접힘 상태와 같은 이유다. 강조는 서버와 무관한 화면 상태라 undo 대상이 아니다. React Flow 노드의 `className`에 써 넣는 방식도 삭제 기록과 실패 복구용 보관값에 함께 담기므로 쓰지 않는다.

`CustomNode`는 자기 `id`가 강조 집합에 있는지만 boolean으로 구독한다. 강조 집합이 바뀌어도 결과가 같은 노드는 다시 그려지지 않는다. 테두리는 래퍼 `.react-flow__node`가 그리므로 `.custom-node`의 `data-highlighted`를 `:has()`로 읽어 래퍼에 `outline`을 그린다. 선택은 `border-color`를 바꾸므로 강조된 노드를 선택해도 둘 다 보인다.

편집기를 벗어날 때 `useInitializeTree`의 언마운트 effect가 `resetTree`·`resetCollapse`와 함께 강조를 비운다.

### 검색과 태그는 결과 영역을 번갈아 쓴다

강조 집합과 결과 목록은 하나뿐이므로 둘이 동시에 켜지지 않는다. 워크스페이스 패널은 태그를 고르면 검색어를 지우고, 검색어를 입력하면 태그 선택을 푼다.

강조는 패널이 지금 보이는 결과를 `useHighlightResults` 하나에 넘겨 반영한다. 검색과 태그가 각자 effect로 강조를 쓰면 결과가 빈 쪽의 effect가 다른 쪽의 강조를 지운다. 검색어가 비면 검색 결과는 `[]`이므로, 태그를 고르는 순간 태그 강조가 사라진다.

고른 태그가 트리 태그 목록에서 사라지면 고르지 않은 것으로 본다. 태그를 지울 때 패널의 선택 state를 따로 비우지 않아도 결과와 강조가 함께 풀린다.

### 펼치기와 선택은 한 렌더에 반영한다

`focusNode`는 접힌 조상 펼치기와 선택을 같은 이벤트 handler 안에서 동기로 한다. 선택만 먼저 반영되면 대상이 아직 숨겨진 상태라, `useVisibleElements`가 "선택된 노드가 숨겨졌다"고 보고 선택을 풀고 메모 패널을 닫는다.

여러 조상은 `expandAll`로 한 번에 펼친다. `expand`를 조상마다 부르면 그때마다 `localStorage`에 쓰고 다른 탭에 `storage` 이벤트를 일으킨다.

선택은 `selectOnlyNodeInStore`로 바꾼다.

### 화면 이동은 레이아웃 뒤에 한다

숨겨져 있던 노드는 펼친 뒤의 레이아웃이 끝나야 좌표가 생긴다. 그 전의 store 좌표는 숨기기 전 좌표거나 원점이다.

- `useEditorLayout`은 `runAfterNextLayout(callback)`으로 "다음 레이아웃 결과를 얹은 뒤 함수 하나를 실행"하는 것만 맡는다. 맡긴 함수는 하나만 두고, 기다리는 사이 새로 맡기면 나중 것으로 덮는다. 최신 계산이 실패하면 버린다. 남겨 두면 나중의 관계없는 레이아웃 뒤에 실행된다.
- `useFocusNode`는 대상이 보이는 노드이고 레이아웃 계산 중이 아닐 때만 바로 옮긴다. 계산 중이면 보이는 노드도 기다린다. 그렇지 않으면 접힌 형제 둘을 연달아 눌렀을 때, 두 번째 노드는 바로 옮겨지고 첫 클릭이 미뤄 둔 이동이 레이아웃 뒤에 실행되어 마지막 클릭을 덮는다.
- 이동은 다음 프레임에 렌더된 노드의 상자를 읽어 그 가운데로 `setCenter`를 부른다. `setCenter`는 `zoom`을 빼면 `maxZoom`으로 확대하므로 현재 배율을 넘긴다.

### 태그로 모을 때는 펼치지 않는다

태그를 고르면 `fitNodes`가 그 태그가 붙은 노드들을 `fitView`로 한 화면에 모은다. 선택은 바꾸지 않는다. 최대 배율은 트리 맞춤과 같은 1로 둔다. 노드가 하나뿐이면 `maxZoom`까지 확대되기 때문이다.

접혀서 숨겨진 노드는 펼치지 않고 대상에서 뺀다. 태그를 둘러보는 것만으로 사용자의 접힘 상태(`localStorage`, 다른 탭)를 바꾸지 않기 위해서다. 숨겨진 노드는 결과 목록에 남아 있고, 누르면 `focusNode`가 조상을 펼쳐 찾아간다. 보이는 노드가 하나도 없으면 화면을 옮기지 않는다.

## 노드 태그

노드에 붙은 태그는 편집기 노드의 `data.tagIds`에 붙인 순서대로 둔다. 메모 패널은 선택 노드의 `tagIds`를 읽고, 태그 결과는 store 전체 노드에서 그 ID를 가진 노드를 찾는다. 노드마다 태그를 따로 조회하지 않는다.

`tagIds`는 트리 조회 응답의 노드마다 실려 오고, `TreeNode`를 거쳐 초기화 때 `data.tagIds`로 옮겨진다. 새로 만든 노드는 태그 없이 `[]`로 시작한다.

트리 태그 목록은 화면이 `useTreeTags`로만 읽고 쓴다. 목록은 트리 태그 query cache가 원본이라 화면이 cache에서 바로 그린다. 그래서 태그 생성·삭제는 노드 태그와 달리 store에 먼저 반영하지 않고 서버 응답을 받은 뒤 cache에 반영된다. 트리 ID는 editor store에서 읽으므로 편집기가 초기화되기 전과 벗어난 뒤에는 조회하지 않는다.

노드에 태그를 붙이고 떼는 일은 store에 먼저 반영하고 서버에 요청한다. 새 이름으로 붙이면 태그 ID가 있어야 하므로 트리 태그를 먼저 만들고 응답을 받은 뒤 붙인다. 이때 연결만 실패하면 태그는 트리에 남는다. 서버에 저장되기 전인 노드(`serverId`가 `null`)에는 요청을 보낼 수 없어 막는다.

태그 store action은 `tagIds`만 바꾼다. 요청이 실패하면 반대 action으로 그 태그만 되돌린다(actions README의 "값 단위 편집은 바꾼 값만 되돌린다"). 태그를 붙이고 떼는 편집 자체는 undo 대상이 아니다. 노드 추가·삭제를 undo/redo해 노드를 되살릴 때는 지운 시점의 `tagIds`와 메모를 함께 되살린다.

태그 이름이 같은지는 앞뒤 공백을 지우고 대소문자를 무시해 비교한다(`getNormalizedTagName`). 백엔드의 이름 유니크 제약은 대소문자를 구분하지만, 같은 개념의 태그가 표기만 달리해 갈라지지 않도록 프론트가 정한 제품 규칙이다. 프론트가 더 엄격하므로 이 차이로 거절되지는 않는다. 다른 경로로 대소문자만 다른 두 태그가 이미 있으면 먼저 찾은 태그를 쓴다.

## 강의 데모

트리 위에서 강의를 재생한다. 장면마다 노드 하나를 설명하고, 비트마다 음성·자막·연출이 함께 진행된다. 플레이어는 `LectureScript` 한 가지 형식만 재생한다. 재생할 대본은 `useLectureScript`가 고른다. 지금 트리로 만든 강의가 있으면 그것을, 없으면 트리에 맞는 `entities/lecture`의 데모 강의를 쓴다.

시작 전 플레이어 자리에서 강의를 만들 수 있다. `LectureGenerator`가 요청 문장을 받고, `useGenerateLecture`가 편집기 트리의 outline으로 요청해 응답을 대본으로 컴파일한다. 고칠 수 있는 문제가 있으면 repair를 한 번 보낸다. 만든 대본은 `generatedLectureStore`에 트리별로 하나씩 둔다. 같은 트리의 요청이 겹치면 마지막에 시작한 요청의 대본만 남긴다. 백엔드가 아직 강의를 저장하지 않아 새로고침하면 사라진다.

### 데모 강의와 노드 연결

대본은 서버 노드 ID로만 노드를 가리킨다. 그러나 노드 ID는 저장할 때마다 DB가 새로 부여하므로 데모 대본에 고정할 수 없다. 그래서 데모 강의는 노드 이름 경로를 함께 갖고, `findDemoLectureScript`가 지금 트리에서 경로를 따라 서버 ID를 찾아 일반 `LectureScript`를 만든다. 경로 하나라도 찾지 못하거나 대상 노드가 아직 저장되지 않았으면 그 데모는 이 트리에 맞지 않는 것으로 본다.

이름 경로는 이 데모 경로 안에만 있다. 재생 쪽 코드는 서버 ID만 알고, `getEditorLectureScript`가 실행 전에 clientId로 바꾼다. 서버가 강의를 내려주게 되면 `useDemoLectureScript`를 강의 조회 query로 바꾸고 데모 경로를 지운다.

고구려 트리는 개발용 화면(`/dev/demo-trees`)에서 버튼으로 DB에 만든다. 원본은 `DEMO_TREES`이고 대본의 이름 경로와 같은 상수를 쓴다. 나머지 데모를 보려면 새 워크스페이스에서 편집기로 아래 트리 중 하나를 직접 만든다. 데모 구조 밖의 노드가 더 있어도 되고, 형제 순서는 연결에 영향을 주지 않는다. 만든 강의도 맞는 데모도 없는 트리에서는 플레이어 자리에 `강의 만들기` 버튼만 보여 준다. 강의 중에 노드 이름을 바꿔 대본을 찾지 못하게 되어도 진행 중인 강의는 시작할 때 연결한 대본으로 계속된다.

```text
│  ├─ 살수대첩
│  └─ 안시성 전투
└─ 멸망
   ├─ 연개소문
   └─ 나당 연합군
```

### 연출은 제한된 동작을 조합한다

`LectureScript`는 장면(`scene`) 아래에 음성·자막·연출의 동기화 경계인 `beat`를 두고, 각 비트가 `focus`·`highlight`·`dim`·`trace`·`collapse`·`expand`·`reset` 동작을 갖는다. `group`은 이 동작들을 `sequence` 또는 `parallel`로 재귀 조합한다. LLM은 이 대본이나 브라우저에서 실행할 코드를 직접 만들지 않고 `LectureScenario`만 만든다. `getLectureGenerationResult`가 모델 응답을 JSON, 스키마, 컴파일 순서로 검사해 대본으로 바꾼다. 응답 처리는 `docs/specs/lecture-generation.md`, 대본 계약은 `docs/specs/lecture-script-contract.md`에 둔다.

`getEditorLectureScript`는 실행 전에 대본 안의 모든 서버 노드 ID를 편집기 노드의 `data.serverId`와 비교해 React Flow clientId로 바꾼다. ID 하나라도 현재 트리에 없으면 대본 전체를 거부한다. 변환 뒤에는 `runLectureAnimation`이 조합을 해석하고, `lectureAnimationStore`가 강조·흐림·연결선 추적을 동작별 레이어로 관리한다. 병렬 동작이 각각 자기 레이어만 제거하므로 같은 종류의 효과를 서로 덮어쓰지 않는다.

`persist`가 없는 시각 동작은 `durationMs` 뒤에 자기 레이어를 제거한다. `persist: true`인 동작은 즉시 다음 동작으로 진행하면서 같은 장면 동안 효과를 유지한다. `reset`이 먼저 지울 수 있고, 장면 전환·정상 종료·사용자 종료·재시작·언마운트에서는 플레이어가 남은 레이어를 자동 정리한다. 일시정지는 현재 화면을 보존한다. 실행 신호가 중단되면 대기 중인 일회성 동작을 정리하고 이후 순차 동작은 실행하지 않는다.

Pulse는 React Flow가 좌표 배치에 쓰는 `transform`을 건드리지 않고 box-shadow만 움직이며, Trace는 연결선의 굵기·광원·흐르는 점선으로 방향을 드러낸다. 모든 트리 엣지는 기존 smooth step 모양을 유지하는 `CustomEdge`로 렌더링되어 추적 상태를 직접 구독한다.

애니메이션은 개발 전용 화면 `/dev/animation-lab`([Animation Lab](../../widgets/animation-lab/README.md))에서 조합하고 재생해 볼 수 있다. 이 route는 production에서 `notFound()`로 막는다.

### 상태는 위치 하나에서 파생한다

`lecture/lectureStore`는 재생 상태(`idle`·`playing`·`paused`·`ended`)와 장면·비트 위치, 시작할 때 연결한 대본만 갖는다. 음성과 자막, 현재 노드 강조는 각자 상태를 두지 않고 이 위치를 읽는다. 따로 두면 서로 어긋날 수 있다. 접힘·강조 store와 같은 이유로 treeStore와 분리해 undo history에 들어가지 않는다.

강의 강조는 검색·태그 강조 집합과 따로 둔다. 하나를 같이 쓰면 강의 중에 검색할 때 강의 강조가 지워진다. `CustomNode`는 현재 장면의 중심 노드인지 boolean으로 구독하고 `data-lecture-current`로 알린다. 대본에 `highlight` 동작이 없어도 설명 중인 노드는 항상 강조된다. `highlight` 동작이 실행되는 동안에는 그 색이 우선한다. 선택은 border, 검색·태그 강조는 outline, 강의 강조는 box-shadow로 그려 셋이 겹쳐도 모두 보인다. 강의가 끝나면 강조를 푼다.

### 음성은 비트 하나씩 읽는다

`useLecturePlayback`은 지금 비트의 내레이션을 `SpeechSynthesis`로 읽으면서 연출을 함께 시작하고, 둘 다 끝나면 다음 비트로 넘긴다. 그래서 자막은 비트 단위로 음성과 맞는다. 브라우저 음성 합성은 단어 단위 시각을 주지 않으므로 그보다 세밀하게 맞추지는 않는다.

- **일시정지는 끊고, 재개는 지금 비트를 처음부터 재생한다.** `pause()`·`resume()`은 브라우저마다 동작이 달라 재개해도 소리가 나지 않는 경우가 있다. 강의 전체를 한 발화로 읽지 않고 비트의 내레이션을 짧게 두는 것도 Chrome에서 긴 발화가 15초 무렵 끊기기 때문이다.
- **한국어 음성이 없으면 음성 없이 `fallbackDurationMs`만큼 기다린다.** lang만 `ko-KR`로 두고 읽게 하면 다른 언어 음성으로 읽거나 소리 없이 넘어가는데, 화면은 음성이 나오는 것처럼 보인다. 음성 합성이 실패해도 같은 방식으로 바꾼다. 플레이어는 재생 방식을 항상 표시한다.
- **늦게 도착한 이벤트는 두 겹으로 막는다.** 일시정지·장면 이동·언마운트는 모두 effect cleanup으로 읽던 내레이션과 연출을 끊고, 끊긴 내레이션의 이벤트는 `playSentence`가 무시한다. 비트 완료는 끝난 위치를 함께 넘기고, 지금 위치와 다르면 store가 무시한다.

### 음성 설정

음성 종류, 음량, 속도, 음소거는 `shared/lib/speech`의 음성 설정에 기기별로 저장한다. 값은 설정 페이지의 `features/voice/select-voice`에서 고르고, 음소거만 플레이어에서 바꾼다. 설정 UI와 이 feature가 함께 쓰므로 `playSentence`와 음성 구독도 `shared`에 둔다.

- **고른 음성이 없으면 자동 선택으로 돌아간다.** 쓸 수 있는 음성은 기기와 브라우저마다 다르기 때문이다.
- **고를 수 있는 음성은 자연스러운 이름 패턴에 맞는 것만이다.** Google, Edge 신경망, macOS 고품질 음성과 Yuna가 해당한다. Eddy, Grandma 같은 macOS 기본 음성은 강의를 듣기 어려워 목록에서 뺀다. 패턴에 맞는 음성이 없는 기기에서는 자동 선택이 남은 한국어 음성으로 읽는다.
- **재생 중에 바꾸면 다음 문장부터 적용한다.** 이미 읽기 시작한 문장의 음성, 음량, 속도는 바꿀 수 없고, 다시 읽으면 화면 연출과 어긋난다. 음소거만 바로 반영한다.
- **끝 이벤트를 기다리는 상한은 속도로 나눈다.** 그러지 않으면 느린 속도의 정상 낭독이 상한에 걸려 끊긴다. 음성 없이 넘어가는 자막 시간에는 속도를 적용하지 않는다.

### 키보드로 강의를 조작한다

강의가 진행되는 동안 `Space`는 일시정지와 재생, `←`·`→`는 이전·다음 비트, `Shift`를 함께 누르면 이전·다음 장면, `R`은 지금 비트 다시 듣기, `M`은 음성 켜기·끄기, `F`는 설명 중인 노드로 카메라 복귀, `Esc`는 강의 종료다. 입력 중이거나 메뉴가 열려 있으면 동작하지 않고, 버튼에 포커스가 있으면 `Space`는 버튼을 누르는 키로 남긴다. 강의 중에는 React Flow의 방향키 노드 이동과 노드 선택 키를 끈다.

위치를 옮기면 대본을 처음부터 따라가 그 위치의 접힘, 유지되는 강조, 마지막 카메라를 다시 계산한다(`getLectureSeekState`). 비트 동작은 앞으로만 진행하므로 뒤로 가도 앞 비트가 바꾼 상태가 돌아오지 않기 때문이다. 강의 중에 사용자가 직접 접은 것은 이때 사라진다. 일시정지 중에 옮기면 일시정지를 유지하고 유지되지 않는 강조까지 그 비트의 연출을 보여 주며, 재생하면 그 연출을 걷어 내고 비트를 처음부터 시작한다. 병렬 그룹은 재생기와 같은 시각표로 펼쳐 재생한 결과와 같은 접힘을 만든다. `R`은 일시정지 중에도 재생을 시작한다.

음성을 켜고 꺼도 비트를 다시 시작하지 않는다. 끄면 자막을 읽을 남은 시간만 기다렸다 넘어가고, 켜면 화면 연출은 그대로 둔 채 지금 문장을 처음부터 읽는다. 끈 상태는 음성 설정에 저장되므로 새로고침해도 유지된다. 음성 합성을 쓸 수 없으면 켤 음성이 없으므로 버튼 대신 안내를 보여 주고 `M`은 동작하지 않는다.

`F`는 마지막 카메라 동작을 다시 실행한다. 강의 중에 화면을 옮겨 본 뒤 돌아오는 키다. 아직 카메라 동작이 없는 위치에서는 움직이지 않는다. 다시 실행할 때는 접힘을 바꾸지 않는다. 처음처럼 조상을 펼치면 대본이 그 뒤에 접은 것이 풀리기 때문이다. 그래서 대상이 접혀 숨어 있으면 화면도 옮기지 않는다.

### 카메라는 시각 프레임을 기준으로 맞춘다

패널과 플레이어는 캔버스의 일부를 가린다. 캔버스를 가리는 UI는 `data-camera-inset`에 가리는 쪽을 적고, `useCameraMove`는 움직일 때마다 그 크기를 재서 가리지 않는 영역(시각 프레임)에 노드를 맞춘다. 패널이 캔버스와 나란히 놓이면 겹치지 않아 빠지지 않고, 좁은 화면에서 겹쳐 뜨면 겹친 만큼 빠진다. 호출하는 쪽은 여백을 넘기지 않는다.

강의 중에 패널이 열리거나 닫히면 마지막 카메라 동작을 다시 실행해 설명 중인 노드를 새 프레임에 맞춘다. 편집 중에는 메모를 열 때마다 보던 지점을 잃지 않도록 움직이지 않고, 다음 카메라 동작부터 새 프레임을 쓴다. 자막 때문에 플레이어 높이가 달라지는 것도 비트마다 화면이 흔들리므로 다음 카메라 동작 때 반영한다.

### 카메라는 `focus` 동작이 옮긴다

카메라는 대본의 `focus` 동작이 실행될 때만 움직인다. 대상 노드, 배율 상한, 이동 시간은 동작이 정한다. `focus`가 없는 비트에서는 사용자가 옮겨 둔 화면을 건드리지 않는다. 재개는 지금 비트를 처음부터 재생하므로 그 비트에 `focus`가 있으면 화면이 대상 노드로 돌아간다.

`revealNodes`는 보이는 노드가 바뀔 때마다 새 함수가 된다. `useLecturePlayback`이 이 함수에 반응하면 접힌 노드를 펼치거나 트리를 편집할 때 읽던 비트가 처음부터 다시 시작되므로 effect event로 감싼다.

태그의 `fitNodes`와 달리 `revealNodes`는 접혀서 숨겨진 대상의 조상을 펼친다. 강의가 가리키는 노드가 화면에 없으면 자막과 강조가 가리킬 대상이 사라지기 때문이다. 펼친 노드는 레이아웃이 끝나야 좌표가 생기므로 `focusNode`와 같이 `runAfterNextLayout`으로 미룬다.

강의 중의 접힘은 임시다. `focus`가 펼치고 `collapse`·`expand`가 바꾼 접힘은 메모리에만 반영하고 localStorage에 쓰지 않으며, 강의가 끝나거나 멈추면 시작할 때의 상태로 돌아가 카메라를 다시 맞춘다. 강의를 봤다고 사용자가 정리해 둔 트리 모양이 바뀌면 안 되기 때문이다. 그동안 사용자가 직접 접은 것도 함께 되돌아가고, 다른 탭의 변경은 돌아갈 상태에 반영한다. Animation Lab은 재생기를 직접 호출하므로 임시 접힘을 쓰지 않는다.

강의는 편집을 막지 않는다. 강의 중에 대상 노드를 삭제하면 그 노드에 대한 강조와 카메라 이동 없이 자막은 그대로 진행된다.

## 레이어 선택 배경

Tree Editor는 여러 UI 요소와 편집 기능을 조합해 하나의 큰 화면 영역을 구성하므로 역할만 보면 `widgets` 레이어가 자연스럽다. 하지만 편집기 전용 상태와 노드 추가·삭제 같은 행동이 서로 긴밀하게 의존한다. 이를 Widget과 여러 Feature로 분리하면 Feature가 Widget의 상태나 로직을 참조할 수 없어 FSD의 하위 레이어 참조 규칙을 위반하거나, 규칙을 지키기 위해 상태와 인터페이스를 여러 슬라이스로 나누어 전달해야 한다.

현재는 참조 규칙을 지키면서 불필요한 경계와 연결 복잡도를 늘리지 않기 위해 Tree Editor 전체를 하나의 Feature로 두었다. 대신 규모가 큰 내부 로직은 `model` 아래에서 `actions`, `initialization`, `collapse`, `layout`, `react-flow`, `search`, `tag`, `highlight`, `focus`, `lecture` 책임으로 구분한다. 이는 모든 Feature에 적용하는 공통 규칙이 아니라 Tree Editor의 응집도와 레이어 의존성을 고려한 예외적인 선택이다.

외부 레이어는 내부 경로를 직접 참조하지 않고 루트 `index.ts`의 공개 API를 사용한다.
