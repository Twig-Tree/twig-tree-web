# Node Action Lab

노드 동작(메모 열기, 자식 추가, 이름 편집, 삭제)을 어떤 방식으로 찾고 실행하게 할지 비교하는 개발 전용 widget이다. route는 `app/(dev)/dev/node-action-lab/page.tsx`이고 production에서는 `notFound()`로 막는다. 운영 기능은 이 모듈에 의존하지 않는다. 배경은 #170에 있다.

지금 제품은 노드를 우클릭해야 동작이 보이고, 키보드로는 노드를 추가하거나 지울 수 없다. 여기서 진입 방식을 켜고 끄며 조합해 보고, 채택한 방식은 제품 편집기에 따로 넣는다.

## 제품과 같은 점, 다른 점

제품의 `nodeTypes`, `edgeTypes`, `useEditorLayout`, `useVisibleElements`, `useNodeTransition`을 그대로 쓴다. 노드 모양이 제품과 같아야 메뉴·버튼·입력창이 노드를 가리는지 실제 모습으로 볼 수 있다.

트리는 `model/fixtureTree.ts`의 고정 데이터로 `useInitializeTree`를 거쳐 채운다. 서버에 조회나 저장을 하지 않으므로 인증 없이 열린다. "트리 처음 상태로"는 트리 ID 끝의 회차를 올려 store를 다시 채운다.

|           | 제품                          | 실험실                                              |
| --------- | ----------------------------- | --------------------------------------------------- |
| 동작 실행 | 서버 요청 후 실패하면 되돌림  | store에서만 실행 (`model/useLabNodeActions.ts`)     |
| 막는 조건 | 루트 삭제 금지 등             | 같게 막고, 막힌 이유를 메뉴·툴팁·기록에 보여 준다   |
| 이름 편집 | 노드 더블클릭, 노드 안 입력창 | 메뉴·버튼·단축키로 노드 위에 실험실 입력창을 겹친다 |
| 메모 열기 | 메모 편집 패널                | 대상 노드만 보여 주는 자리 표시 패널                |
| 노드 끌기 | 끌어서 부모·순서 변경         | 끈다 (`nodesDraggable={false}`)                     |

노드를 더블클릭하면 제품 이름 편집기가 그대로 열리지만, 저장은 서버 요청이라 실패한다. 실험실 트리 ID가 숫자가 아니라 실제 트리에 닿지는 않는다.

이름 입력창은 캔버스를 축소해도 원래 크기로 그린다. 캔버스 좌표에 두면 최소 배율(0.3)에서 몇 픽셀로 줄어 열린 줄 모른다.

## 진입 방식

왼쪽 패널에서 고르고, 설정은 `model/config.ts`의 한 객체다.

| 묶음         | 옵션            | 선택지                                       |
| ------------ | --------------- | -------------------------------------------- |
| 메뉴         | 여는 방법       | 우클릭 / 클릭 / 선택된 노드 다시 클릭 / 끄기 |
|              | 단축키 표기     | 켜기 / 끄기                                  |
| 노드 옆 버튼 | 보이는 때       | 끄기 / 호버 / 선택 / 둘 다                   |
|              | 위치            | 오른쪽 / 아래 / 위                           |
|              | 모양            | 아이콘 / 아이콘 + 글자                       |
|              | 툴팁            | 끄기 / 이름, 단축키 표기 체크박스            |
| 키보드       | 기준 운영체제   | 이 기기 / Mac / Windows                      |
|              | 하단 힌트 줄    | 켜기 / 끄기                                  |
|              | `?` 단축키 안내 | 켜기 / 끄기                                  |

단축키는 끌 수 없다. 설정은 새로고침하면 기본값으로 돌아가는데, 끌 수 있으면 꺼진 기본값으로 돌아가 단축키가 동작하지 않는 것처럼 보였다.

### 프리셋

`model/presets.ts`에 비교할 조합 다섯 가지를 둔다. 프리셋을 골라도 단축키 기준 운영체제는 바꾸지 않는다. 지금 설정과 똑같은 프리셋은 눌린 상태로 보이고, 하나라도 바꾸면 풀린다.

| 프리셋         | 조합                                              |
| -------------- | ------------------------------------------------- |
| 지금 제품      | 우클릭 메뉴만                                     |
| A. 클릭 메뉴   | 클릭으로 메뉴, 메뉴에 단축키 표기                 |
| B. 호버 버튼   | 호버 아이콘 버튼, 툴팁에 단축키                   |
| C. 선택 툴바   | 선택한 노드 아래 글자 버튼, 하단 힌트 줄          |
| D. 키보드 중심 | 우클릭 메뉴 + 메뉴 단축키 표기, 힌트 줄, `?` 안내 |

### 결과 공유

"현재 설정 복사"는 패널과 같은 이름의 목록과 설정 JSON을 함께 복사한다. 어떤 조합에서 무엇이 불편했는지 이슈나 대화에 옮길 때 쓴다. 실행 기록에는 `진입점 · 동작 · 노드`와 막힌 이유가 최근 순서로 남는다.

## 단축키

표는 `model/shortcuts.ts` 하나이고, 메뉴·툴팁·힌트 줄·안내가 모두 이 표를 읽는다. 노드를 하나 선택했을 때만 동작한다.

| 동작                  | Windows           | Mac     | 이유                                                                |
| --------------------- | ----------------- | ------- | ------------------------------------------------------------------- |
| 메모 열기             | Enter             | Space   | 맥은 Return이 이름 편집이라 Finder 미리 보기처럼 Space로 연다       |
| 자식 추가             | →                 | →       | 트리가 오른쪽으로 자란다. Tab은 focus 이동 키라 쓰지 않는다         |
| 이름 편집             | F2                | Return  | 각 운영체제 파일 탐색기의 이름 바꾸기. 맥의 F2는 기본으로 밝기 키다 |
| 삭제                  | Delete, Backspace | ⌫, fn+⌫ | #169에서 React Flow 기본 삭제 키로 끈 키를 삭제 동작에 다시 잇는다  |
| 선택 해제             | Esc               | Esc     |                                                                     |
| 노드 옆 버튼으로 이동 | Tab               | Tab     | 노드 옆 버튼이 "선택"이나 "둘 다"일 때                              |

수정키가 붙은 키(Shift+→, ⌘→ 등)는 노드 동작으로 받지 않는다. 텍스트 선택이나 브라우저 단축키를 가로채게 된다.

### 키를 받지 않는 때

판단은 `model/useLabShortcuts.ts`가 하고, 기준은 강의 키보드 조작(`useLectureKeyboard`)과 같다.

- 입력창에 focus가 있거나 메뉴·대화상자가 열려 있으면 그 UI의 키다.
- 동작 단축키는 focus가 캔버스 안이나 페이지 바탕에 있을 때만 받는다. 설정 패널에서 누른 키가 노드를 바꾸면 안 된다. `?`는 어디서든 받는다.
- 노드 옆 버튼 같은 일반 버튼의 Enter·Space는 버튼을 누르는 키라 넘긴다. 노드 제목 버튼은 예외다. 노드를 누르면 focus가 여기에 가는데, 제품 노드는 이 버튼의 Enter·Space로 서버 저장을 거치는 이름 편집을 시작하고 전파를 막는다. 그래서 capture 단계에서 먼저 받는다.
- Escape로 선택을 풀면 React Flow까지 전파하지 않는다. React Flow는 노드에 focus가 있을 때 Escape를 받으면, 이미 풀린 노드를 다시 선택한다.

## 실험하며 드러난 점

제품에 넣을 때 함께 봐야 하는 것들이다.

- **노드 옆 버튼은 Tab 순서로 닿지 않는다.** React Flow의 `NodeToolbar`는 모든 노드 뒤에 그려진다. 선택한 노드에서 Tab으로 첫 버튼에 보내고, 버튼 안에서는 ←→·Home·End로 오가며, Esc·Shift+Tab으로 노드에 돌아오게 했다. 호버로만 보이는 버튼에는 키보드로 들어갈 수 없다.
- **마우스로 누른 버튼이 focus를 가져가면 단축키가 버튼으로 간다.** Enter·Space가 방금 누른 버튼을 다시 누른다. 노드 옆 버튼은 마우스로 누를 때 focus를 가져가지 않는다.
- **마우스로 연 메뉴의 첫 항목 focus는 보이지 않는다.** 브라우저는 마우스 다음에 옮긴 focus를 표시하지 않아, Tab이 보이지 않는 첫 항목을 건너 둘째 항목으로 간다. 실험실 메뉴는 메뉴 자체에 focus를 둔다. 제품 `NodeContextMenu`도 같은 구조다.
- **클릭 메뉴는 더블클릭 이름 편집과 부딪힌다.** 첫 클릭에 메뉴가 열렸다가 이름 편집이 시작되며 닫힌다.
- **오른쪽 버튼은 자식 노드를 가린다.** 트리가 오른쪽으로 자라는 배치라 버튼이 이웃 노드 위에 놓인다. `NodeToolbar`의 기본 z-index(노드 z + 1)는 노드 층보다 낮아 4로 올렸다.
- **방향키를 이웃 노드 이동에 쓰면 → 자식 추가와 겹친다.** #127의 추천 기능을 넣을 때 다시 정한다.
